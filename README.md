# BattleMarmot: прятки сурков в степи

**Играть:** https://battlemarmot.vercel.app
**Тестовый аккаунт:** `tester@battlemarmot.app` / `marmot2026` (можно зарегистрировать и свой, подтверждение почты не требуется)

BattleMarmot это классический «Морской бой», перенесённый в казахскую степь. Вместо кораблей сурки, вместо моря степь с тюльпанами и ковылём, вместо стрельбы прятки. Каждый прячет своих сурков в норках, и побеждает тот, кто первым найдёт всех сурков соседа.

Проект сделан на технический этап отбора **Narxoz Incubator 2026** (вариант задания: «Морской бой»).

---

## Для кого и чем отличается

**Для кого:** для всех, кто хочет сыграть пару коротких партий в перерыве, с компьютера или телефона, без установки и без обязательной регистрации.

**Чем BattleMarmot отличается от «ещё одного морского боя»:**

- **Не бой, а прятки.** Механика классическая, но настроение другое, мирное и милое. Промах означает пустую норку, при попадании из норы выглядывают ушки, а найденный целиком сурок вылезает со звёздочкой.
- **Локальный колорит.** Сурки живут в казахской степи. На поле растут красные и жёлтые тюльпаны, ковыль и полынь, а соперники тоже степные: жаворонок, лиса и беркут.
- **Соперники с характером.** У каждого уровня сложности свой пиксельный портрет, и его выражение меняется по ходу партии: в свой ход он думает («…»), найдя сурка радуется, а когда игрок его обгоняет, нервничает и потеет.
- **Весь визуал нарисован вручную для проекта.** Все спрайты (сурки, соперники, норки, тайлы поля, иконки) нарисованы с нуля в пиксель-арте и описаны в коде как массивы строк. Ни одной сторонней картинки.
- **Живая главная страница.** Сурки летают на воздушных шариках, выглядывают из норок, на них можно нажимать: маленькие сердятся и ныряют в норку, поднимая песок, большие вытягиваются столбиком, спящий длинносурок ворчит, если его разбудить.
- **«Давай ещё одну».** После партии одна кнопка запускает реванш, а расстановку можно повторить «как в прошлый раз».

## Правила игры

1. У каждого игрока поле 10×10 (столбцы А–К, строки 1–10) и 10 сурков:
   - Длинносурок (4 клетки) × 1
   - Большой сурок (3 клетки) × 2
   - Сурок (2 клетки) × 3
   - Сурчонок (1 клетка) × 4
2. Сурки стоят прямо, лёжа или столбиком, и **не касаются друг друга даже углами**.
3. Игроки по очереди заглядывают в клетки поля соперника:
   - **Пусто**: ход переходит сопернику;
   - **Попался!**: найдена часть сурка, игрок ходит ещё раз;
   - **Сурок найден**: найдены все его клетки; клетки вокруг автоматически отмечаются как пустые.
4. В одну клетку дважды заглянуть нельзя.
5. Побеждает тот, кто первым найдёт всех 10 сурков соседа.

### Соперники (уровни сложности)

| Соперник | Уровень | Стратегия | Среднее число ходов до победы* |
|---|---|---|---|
| Жаворонок | Лёгкий | В основном ищет наугад, иногда вспоминает, где уже нашёл часть сурка | ≈ 63 |
| Лиса | Средний | «Охота и добивание»: проверяет клетки в шахматном порядке, после попадания ищет рядом и продолжает по линии | ≈ 57 |
| Беркут | Сложный | Карта вероятностей: для каждой клетки считает, сколькими способами в неё могут поместиться оставшиеся сурки с учётом всех известных промахов, попаданий и правила «не касаться» | ≈ 55 |

\* 300 симулированных партий на уровень, скрипт `tools/ai-benchmark.ts`. Для сравнения: полностью случайный поиск занимает ≈ 75 ходов.

## Технологии

- **React 19 + TypeScript + Vite**: интерфейс и сборка
- **Supabase**: база данных PostgreSQL и авторизация (готовый backend-сервис)
  - таблица `games` с политиками **Row Level Security**: каждый пользователь читает и пишет только свои партии (схема в `supabase/schema.sql`)
  - в коде используется только публичный (publishable) ключ: он предназначен для браузера, а доступ к данным ограничен RLS
- **Vercel**: хостинг, автоматический деплой из GitHub при каждом изменении
- **Web Audio API**: 8-битные звуки синтезируются в браузере, без аудиофайлов
- **SVG**: весь пиксель-арт рисуется из строковых спрайтов (`src/ui/sprites.tsx`, `src/ui/Portrait.tsx`, `src/ui/tiles.ts`)

### Структура проекта

```
src/
  game/           игровая логика без интерфейса
    types.ts        типы, состав «флота»
    board.ts        расстановка, проверка правил, выстрел, публичный вид поля
    ai.ts           три стратегии компьютерного соперника
    engine.ts       ход игрока / компьютера, завершение партии, итоги
  lib/
    storage.ts      сохранение в LocalStorage
    history.ts      история и статистика (LocalStorage + Supabase)
    auth.ts         вход и регистрация
    sound.ts        8-битные звуки
  ui/             пиксельные спрайты, поле, портреты соперников, декорации
  screens/        экраны: главная, расстановка, партия, результат, статистика, правила
supabase/schema.sql   схема базы и политики доступа
tools/ai-benchmark.ts симуляция партий для проверки правил и сравнения уровней ИИ
```

## Запуск локально

Нужен Node.js 20+.

```bash
git clone https://github.com/forjaviya/battlemarmot
cd battlemarmot
npm install
npm run dev          # http://localhost:5173
npm run build        # production-сборка в dist/
```

Проект сразу подключается к опубликованной базе Supabase. Чтобы использовать свою, создайте проект в Supabase, выполните `supabase/schema.sql` в SQL Editor и задайте переменные окружения `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

Проверка игровой логики и сравнение уровней ИИ:

```bash
npx tsx tools/ai-benchmark.ts
```

## Известные ограничения

- Игра только против компьютера; мультиплеера с другом по ссылке пока нет.
- Если начать партию на одном устройстве, продолжить её на другом нельзя: незаконченная партия хранится в браузере. На любом устройстве после входа видны законченные партии и статистика.
- Партии, сыгранные гостем, хранятся в браузере и переносятся в аккаунт только при входе с того же устройства.
- Нет восстановления пароля и входа через соцсети.
- Интерфейс только на русском языке.

## Идеи развития

- Игра с другом по ссылке (Supabase Realtime) с проверкой ходов на сервере, чтобы расстановка соперника не попадала в браузер
- Разбор партии: тепловая карта своих поисков и советы, как искать эффективнее
- Косметика (скины сурков, сезонные темы степи) как основа монетизации
